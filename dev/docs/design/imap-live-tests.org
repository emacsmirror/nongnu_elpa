#+TITLE: Live IMAP tests
#+STARTUP: overview

Design for testing =vm-imap.el= against a real server. All 68 existing IMAP
tests are pure spec parsing; there is no coverage of protocol interaction,
which is why #38, #83, #286, #335 and #447 are stuck.

Also the precondition for [[file:async-imap.org][async-imap.org]]: that rewrite is close to
unreviewable without behavioural tests.

Exchange (#389, #391) is out of scope for now.

* Three tiers

| Tier | Needs                | Covers                                        |
|------+----------------------+-----------------------------------------------|
|    1 | nothing              | spec parsing, encoding — what exists today     |
|    2 | dovecot              | UIDVALIDITY, flags, COPY, namespaces, literals |
|    3 | dovecot + relay      | dropped connections, =NO=/=BAD= responses      |

Tier 3 matters because most of the stuck tickets are *error path* bugs and a
healthy server will not produce those states:

| Ticket | Tier | Note                                                    |
|--------+------+---------------------------------------------------------|
| #38    |    2 | attributes lost on save; two mailboxes, check flags     |
| #83    |    2 | same subsystem as #38                                   |
| #447   |    2 | virtual folder over a never-visited IMAP component      |
| #335   |    3 | connection dropped after =SELECT= read as UIDVALIDITY change |
| #286   |    3 | dropped mid =get-new-mail=, then duplicate deletion     |

#286 and #335 share a root cause — VM cannot tell "server said no" from
"connection broke" — so they should be done together.

Tier 3 is a TCP relay written in elisp (=make-network-process :server t=)
between VM and dovecot, scriptable to cut the connection after a chosen
command or rewrite a tagged response. No new dependencies.

* Opt-in

The whole live suite is opt-in. Gate is the *presence* of
=test/vm-imap-config.el= (gitignored) *and* the enable flag that only the
live runner sets. So:

- =make test= :: never contacts a server, even on a configured box.
- =make test-imap= :: loads the config, sets the flag, runs the live tests.

Test files are named =vm-imap-live-*-test.el=, so normal discovery picks them
up and they =skip-unless= the flag. No separate destructive opt-in: the
accounts are throwaway test users.

If the config exists and the enable flag is set but the server is unreachable
or auth fails, *fail* — do not skip. A configured suite that silently skips
rots into permanent no-coverage.

* Configuration

No environment variables. One gitignored elisp file, =test/vm-imap-config.el=:

#+begin_src elisp
(setq vm-imap-test-servers
      '((:name     "plain"
         :host     "127.0.0.1"
         :port     143
         :tls      nil
         :auth     "login"
         :accounts (("vmtest1" . "PASSWORD1")
                    ("vmtest2" . "PASSWORD2")))
        (:name     "tls"
         :host     "localhost"          ; must match the cert subjectAltName
         :port     993
         :tls      t
         :auth     "login"
         :trustfile "/opt/local/etc/dovecot/ssl/vmtest-ca.pem"
         :accounts (("vmtest1" . "PASSWORD1")))))
#+end_src

- Two accounts are required for the cross-account tests (#38, FCC/save);
  single-account tests use the first.
- The harness builds the maildrop spec and populates
  =vm-imap-account-alist=, so tests exercise the nickname path real users
  take rather than raw specs.
- Passwords must not contain =:=. VM's spec is colon-delimited
  (=imap:HOST:PORT:MAILBOX:AUTH:USER:PASSWORD=) and cannot express one.
- =test/vm-imap-config.el= goes in =.gitignore=. Check it against the
  narrowed =*.ind*= pattern, not the old =*.in*=.

* Namespace

Discover it, do not hardcode: issue =NAMESPACE= on connect and take the
personal prefix and separator from the reply.

Mark's dovecot is =mdbox=, so =LAYOUT=fs=: empty prefix, =/= separator.
Maildir++ boxes would give =INBOX.= and =.=. Discovery keeps the suite
portable and is needed anyway to name #447's component folders correctly.

* Fixtures

Per test: create a throwaway mailbox =vmtest/<pid>-<n>=, =APPEND= the
messages it needs, run, and delete it in =unwind-protect=. Never touch
INBOX.

*Fixtures must not be built with VM's own IMAP code.* If setup goes through
=vm-imap-*= then a VM bug corrupts the fixture and masks itself — exactly the
failure mode #286 complains about, where VM acts on data it got wrong. Use a
small independent client in the harness: =open-network-stream= plus
=CREATE=/=APPEND=/=STORE=/=DELETE=, about 40 lines.

=doveadm= is an optional fast path for wholesale reset (=doveadm mailbox
delete -u=). Note =mail_uid = dovecot-mail=, so it likely needs privileges;
pure IMAP stays the default so the suite runs unprivileged and against
non-dovecot servers.

* TLS

VM has *no STARTTLS*. =imap-ssl= is implicit TLS only, via
=open-network-stream :type 'tls= (or stunnel when =vm-stunnel-program= is
set). So:

- In scope :: implicit TLS on 993, native, via =open-network-stream=.
- Not in scope :: STARTTLS on 143 — VM does not implement it. Worth its own
  enhancement issue.
- Not in scope :: the =vm-stunnel-program= branch. It reaches the same place
  by a different route, but needs stunnel installed and configured; decided
  against covering it.

Emacs verifies the certificate through the network security manager. A
self-signed dovecot cert will fail, or worse prompt, and a prompt in batch
hangs. The harness must bind =gnutls-trustfiles= to the =:trustfile= from the
config, and =network-security-level= to =low=, for TLS servers only.

* Hangs

=vm-imap-server-timeout= defaults to =nil=, meaning never. A wedged live
test would hang forever. The harness binds it (10s) and wraps each test in
=with-timeout=. VM's IMAP is synchronous =accept-process-output=; fine in
batch, but these will be slower than tier 1.

* Credentials in output

=vm-imap-log-sessions= logs raw protocol tokens, so a trace contains the
=LOGIN= password in cleartext. Protocol bugs will want traces, so scrub
before attaching one to a failure. Throwaway passwords regardless.

* dovecot changes needed

Step-by-step instructions live in [[file:../dev-guide.org][dev-guide.org]] under
"testing"; this is only what has to change and why.

1. Two test users in the =passwd-file= passdb.  =disable_plaintext_auth = no=
   already allows the IMAP =LOGIN= command on 143.
2. For TLS: =ssl = yes= plus =ssl_cert=/=ssl_key= for a self-signed
   certificate whose *subjectAltName* matches the =:host= in the config.  Not
   the CN -- current GnuTLS checks the SAN and ignores a bare CN, so a
   CN-only certificate fails verification. Out of the box =ssl = no= and no
   certificate is set, so 993 listens but cannot complete a handshake.
3. Optional, for CRAM-MD5: =auth_mechanisms = plain cram-md5= and a passdb
   hash that supports it. VM has a =cram-md5= branch that is untestable
   while =auth_mechanisms = plain=.

Gotchas from that config:

- =mail_max_userip_connections = 10= — tests that leave sessions open can
  hit it; close sessions in =unwind-protect=.
- =auth_failure_delay = 2 secs= — each negative auth test costs 2s.
- =imap_max_line_length = 64 k= — relevant to literal/large-header tests.

* CI

Optional, never required. A container recipe under =test/imap/= so tiers 2
and 3 *can* run in CI; the default pipeline stays tier 1 only.
